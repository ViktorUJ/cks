# Implementation Plan: Перевод глав курса EKS на 8 языков

## Overview

План покрывает четыре последовательных этапа из design.md:

- **Этап A** - Reverse_Mapping_Checker строит Reverse_Mapping_Report (двустороннее
  отображение «лаба <-> глава» на русском оригинале) и точечно исправляет найденные
  Lab_Chapter_Mapping_Gap в `ru.md` затронутых глав, до начала перевода.
- **Этап B** - перевод 53 глав курса **строго последовательно, одна глава за раз**. Каждая
  глава - отдельная задача (не сгруппированная с другими главами в одну задачу). Для каждой
  ещё не начатой главы одновременно запускаются 7 Translation_Subagent: **один агент на один
  язык** (EN, ES, FR, DE, GE, TW, JP); каждый агент создаёт и проверяет только свой
  Chapter_File. После завершения всех 7 агентов выполняется обязательный Self_Check_Process
  по всем 8 Chapter_File главы. Для управляемости 53 главы сгруппированы в 11 групп (10 групп
  по 5 глав + 1 группа из 3 глав) с чекпоинтом после каждой группы - группировка касается
  только контроля прогресса, порядок перевода остаётся строго последовательным по главам.
- **Этап C** - перевод TOC_File и 5 Reference_Doc_File (GLOSSARY, ADR, COST_MODEL, RUNBOOK,
  SCORECARD), после того как известны финальные пути всех 53 глав. Для каждого ещё не
  начатого документа одновременно запускаются 7 Translation_Subagent: один агент на EN, ES,
  FR, DE, GE, TW или JP.
- **Этап D** - точечная правка Chapter_Reference (замена суффикса `ru.md` на `XX.md`) во всех
  README лаб 101-132 на всех 8 языках (256 файлов) - не перевод, а детерминированная замена
  пути ссылки. Для каждой ещё не начатой лабы одновременно запускаются 8 агентов: один на
  каждый README своего языка, включая RU.

> **Приоритет исполнения и выбор агентов для ещё не начатых задач.** Начиная с задачи 17,
> а также для всех последующих ещё не начатых задач этапов C и D, формулировки с «волнами»
> и лимитом в два Translation_Subagent считаются заменёнными этим правилом: для одной главы,
> документа или лабы все её языки запускаются параллельно, и один агент отвечает ровно за
> один язык. Использовать профили `.kiro/agents/eks-translation-<код>.md`: EN, ES, FR, DE,
> TW, JP и RU работают на модели `gpt-5.6-terra`; GE работает на модели `gpt-5.6-sol`. Для этапов B
> и C запускать агентов EN/ES/FR/DE/GE/TW/JP; для этапа D дополнительно запускать RU.
> Детализированные пункты с прежними волнами сохранены только как перечень результата и не
> задают порядок запуска. Задачи 6 и 16, где работа уже была начата, этим правилом не
> изменяются.

Self_Check_Process выполняется оркестратором напрямую (shell/grep), не по отчёту
Translation_Subagent, и является обязательным критерием готовности (требование 9), поэтому
sub-task самопроверки НЕ помечены `*`. Работа не использует программный код и язык
программирования - это генерация и точечная правка markdown-контента по фиксированному
шаблону, поэтому вопрос выбора языка реализации неприменим, а property-based тесты (design.md,
раздел Testing Strategy) не пишутся.

## Notes

- Все sub-task самопроверки (Self_Check_Process) не помечены `*` - в отличие от обычных
  unit/property-тестов кода, они являются обязательным критерием готовности (требование 9) и
  не могут быть пропущены.
- Главы этапа B переводятся строго последовательно, одна за раз (требование 9.1) - следующая
  глава не начинается до прохождения Self_Check_Process текущей главы. Группировка глав по 5
  (10 групп) плюс финальная группа из 3 глав (46-48) с чекпоинтом после каждой группы служит
  только для контроля прогресса и не подразумевает параллельный перевод нескольких глав.
- Для каждой ещё не начатой главы этапа B, а также для каждого ещё не начатого
  TOC_File/Reference_Doc_File этапа C, одновременно запускаются 7 Translation_Subagent:
  по одному на EN, ES, FR, DE, GE, TW и JP. Для каждой ещё не начатой лабы этапа D
  одновременно запускаются 8 агентов: по одному на каждый README соответствующего языка.
  Формулировки задач с прежними волнами не ограничивают этот запуск; каждый агент изменяет
  только файлы своего языка.
- Этап A обязателен до начала этапа B: перевод главы, затронутой Lab_Chapter_Mapping_Gap,
  начинается только после точечного исправления `ru.md` этой главы в задаче 1.4.
- Этап C начинается только после завершения всех 53 глав этапа B (задачи 3-66), так как
  TOC_File и Reference_Doc_File ссылаются на финальные пути Chapter_File всех языков.
- Этап D начинается только после завершения этапа B (задачи 3-66), так как правка
  Chapter_Reference заменяет путь на файл главы, который должен существовать на момент
  правки. Этап D не зависит от этапа C и по данным может выполняться параллельно с ним, но в
  плане идёт после него для простоты последовательного контроля прогресса.
- Property-based тесты не применяются (design.md, раздел Testing Strategy) - вместо них
  используется Self_Check_Process, набор детерминированных shell/grep-проверок,
  выполняемых оркестратором.
