# EKS კლასტერის ხარჯების მოდელი: შეფასების შაბლონი

[კურსის სარჩევი](README_GE.md) · [თავი 43](43/ge.md) · [ტერმინთა ლექსიკონი](GLOSSARY_GE.md)

ეს არის 43-ე თავის სამუშაო ფორმა: ხარჯების იგივე სტრუქტურა, ოღონდ ცხრილისა და ფორმულების სახით,
რომელთა მიხედვითაც ინჟინერი საკუთარი კლასტერის შეფასებას ადგენს. აქ ახალი მასალა არ არის.

## როგორ გამოვიყენოთ

- ფორმა ფასებს არ შეიცავს. ტარიფები რეგიონზეა დამოკიდებული, იცვლება და კურსზე უფრო სწრაფად
  ძველდება, ამიტომ სვეტი „ტარიფი (შეავსეთ)“ განზრახ არის ცარიელი დატოვებული.
- ტარიფები აიღეთ AWS Pricing Calculator-ში თქვენი რეგიონისთვის და ცარიელ სვეტში ჩასვით;
  უკვე მომუშავე კლასტერის ფაქტობრივი მონაცემებისთვის გამოიყენეთ Cost and Usage Report (თავი 43).
- შაბლონის ღირებულება რიცხვის სიზუსტეში კი არა, ჩამონათვალის სისრულეშია: ის არ მოგცემთ იმ
  ხარჯის დავიწყების საშუალებას, რომელიც ანგარიშში გამოჩნდება, მაგრამ შეფასებაში არ მოხვდა.
- შეფასება ორჯერ გააკეთეთ: right-sizing-მდე და მის შემდეგ. ორ გაშვებას შორის სხვაობა
  საინჟინრო გადაწყვეტილების გაზომილი ეფექტია და არა ეკონომიის დაპირება.
- მთელ ფორმაში ერთნაირი ერთეულები გამოიყენეთ (თვეში საათების რაოდენობა, GB და არა GiB),
  წინააღმდეგ შემთხვევაში სტრიქონების მნიშვნელობები ერთმანეთს ვერ დაემატება.
- ფორმა თავიდან შეავსეთ ნოდების შეძენის რეჟიმის შეცვლის, AZ-ის დამატების, ჟურნალების ახალი
  ტიპების ჩართვისა და egress-ის ტოპოლოგიის ნებისმიერი ცვლილების შემდეგ.

## ზოგადი ფორმულები

```text
აღნიშვნები: HOURS - საათების რაოდენობა საანგარიშო თვეში, RATE_* - ტარიფი ზემოთ მოცემული ცხრილიდან,
მოხმარების ყველა სიდიდე აღებულია მეტრიკებიდან და ბილინგიდან და არა საპროექტო გეგმებიდან.

control_plane = CLUSTERS * HOURS * RATE_CP
              + CLUSTERS_EXT * HOURS * RATE_CP_EXT_DELTA
# CLUSTERS_EXT - კლასტერები extended support-ში მყოფ ვერსიაზე: ეს არის ჩვეულებრივი
# საათობრივი საფასურის დანამატი და არა იგივე ტარიფი (თავი 38).

nodes = ჯამი P პულების მიხედვით: NODES[P] * HOURS[P] * RATE_INSTANCE[P, შეძენის რეჟიმი]
# შეძენის რეჟიმი: On-Demand, Spot, Reserved-ით ან Savings Plans-ით დაფარვა (თავი 43).

auto_mode = nodes(Auto Mode-ის პულები)                    # EC2-ის ნაწილი
          + MANAGED_INSTANCES * HOURS * RATE_AM_MGMT       # მართვის დანამატი
# სავალდებულოა: Reserved Instances და Savings Plans ამცირებს მხოლოდ EC2-ის ნაწილს.
# Auto Mode-ის მართვის დანამატზე ეს ფასდაკლებები არ ვრცელდება და ანგარიშში
# ცალკე პოზიციად არის წარმოდგენილი (თავი 09). EKS control plane-ის საათობრივ
# საფასურზეც Compute Savings Plans არ ვრცელდება (თავი 43).

fargate = ჯამი პოდების მიხედვით: VCPU_PROV * LIFETIME_H * RATE_VCPU
        + MEM_PROV_GB * LIFETIME_H * RATE_MEM
# VCPU_PROV და MEM_PROV_GB - CapacityProvisioned ანოტაციაში მითითებული კომბინაციაა,
# ანუ ზემოთ დამრგვალებული requests და არა უშუალოდ requests (თავი 15).

commit_base = BASELINE_COMPUTE - SPOT_SUSTAINED
# BASELINE_COMPUTE გამოითვლება right-sizing-ის შემდეგ, სხვაგვარად ცარიელი რესურსი დაიკომიტება.
# SPOT_SUSTAINED - Spot-ის სტაბილურად მიღწევადი და არა საპროექტო წილია: Savings Plans
# Spot-ს არ ფარავს, საათობრივი კომიტი საათებს შორის არ გადადის და გამოუყენებელი ნაწილი
# ყოველ საათში იკარგება, ხოლო On-Demand-ზე fallback მოხმარების ნაწილს კომიტის ქვეშ აბრუნებს
# (თავები 43 და 13). კომიტი გადაიხედება ფაქტობრივი utilization-ისა და coverage-ის მიხედვით.

nat = NAT_COUNT * HOURS * RATE_NAT_HOUR
    + PROCESSED_GB * RATE_NAT_GB
# ორი დამოუკიდებელი ნაწილი: NAT-ის არსებობისა და თითოეული დამუშავებული გიგაბაიტის საფასური.

cross_az = CROSS_AZ_GB * RATE_CROSS_AZ
# ტარიფი ორივე მიმართულებაზე ვრცელდება: CROSS_AZ_GB მოიცავს მოთხოვნასაც და პასუხსაც (თავი 31).

storage = ჯამი ტომების მიხედვით: SIZE_GIB * RATE_VOLUME[ტიპი]
        + SNAPSHOT_GIB * RATE_SNAPSHOT
# საფასური ტომის გამოყოფილი ზომისთვის გადაიხდება და არა ფაილურ სისტემაში დაკავებული სივრცისთვის.

logs = INGEST_GB * RATE_INGEST + STORED_GB * RATE_STORAGE
# INGEST_GB - მიღებული მოცულობაა: ჩვეულებრივ, სწორედ ის არის ხარჯის მთავარი მუხლი (თავი 34).

total_month = control_plane + nodes + auto_mode + fargate
            + nat + cross_az + egress_internet + storage + logs
            + endpoints + load_balancers
```

## რა ავიწყდებათ ხშირად

- **Auto Mode-ის დანამატი.** ანგარიშში ეს EC2-ის ტარიფის ზემოთ დამატებული ცალკე პოზიციაა და
  ფასდაკლების მოდელები მას არ ეხება; Auto Mode-ის საკუთარ სტეკთან შედარებისას ის ცალსახად
  უნდა დაითვალოს (თავი 09).
- **Extended support, როგორც დანამატი.** მოძველებულ ვერსიაზე მომუშავე კლასტერის საათობრივი
  ღირებულება უფრო მაღალია და არა იგივე; შეფასებაში ეს ცალკე შესაკრებია (თავი 38).
- **Cross-AZ ორივე მიმართულებით.** ერთ ზონაში არსებული სერვისი, რომელიც სხვა ზონაში მდებარე
  ბაზას მიმართავს, იხდის მონაცემთა გაცვლისთვის და არა მხოლოდ მოთხოვნისთვის; დაითვალეთ ორივე მიმართულება (თავი 31).
- **NAT ორჯერ გახდევინებთ.** საათობრივი საფასური ირიცხება, სანამ NAT არსებობს, და მისგან
  დამოუკიდებლად თითოეული დამუშავებული გიგაბაიტიც ფასიანია; ჩვეულებრივ, მეორე ნაწილი ავიწყდებათ (თავი 31).
- **ჟურნალების ხარჯის ძირითადი ნაწილი მიღებაზე მოდის.** retention-ის შემცირება მხოლოდ შენახვას
  ეხება და მცირე ეკონომიას იძლევა; ეფექტურია შეგროვების ინტერვალის, logging level-ებისა და სერიების ფილტრაციის შეცვლა (თავი 34).
- **დავიწყებული ტომები და snapshot-ები.** PVC წაიშალა, ტომი კი დარჩა; snapshot-ები წლების
  განმავლობაში გროვდება. ეს ფარული დანაკარგია, რომელიც მხოლოდ ბილინგში ჩანს (თავი 23).
- **დატვირთვის დამაბალანსებელი წაშლილი სერვისის შემდეგ.** Service Kubernetes-ის გვერდის ავლით
  წაიშალა, NLB ან ALB კი დარჩა და კვლავ ფასიანია (თავი 26).
- **Idle მოცულობა.** იხდით გამოყოფილი requests-ისთვის და არა გამოყენებულისთვის: requested-სა
  და used-ს შორის სხვაობა რეპლიკების რაოდენობაზე გამრავლებული ფასიანი სიცარიელეა (თავი 43).

## ოპტიმიზაციის თანმიმდევრობა

1. **Right-size და bin-pack** - requests მოარგეთ რეალურ მოხმარებას და consolidation-ს ნოდების
   უფრო მჭიდროდ შევსების საშუალება მიეცით (თავები 43, 14, 12).
2. **კომიტი სტაბილურ baseline-ზე** - Savings Plans გამოიყენეთ იმ მოცულობისთვის, რომელიც
   შემცირების შემდეგაც თვეების განმავლობაში ნარჩუნდება (თავი 43).
3. **Spot მოქნილი დატვირთვებისთვის** - წყვეტადი დატვირთვები Spot-ზე გადაიტანეთ ტიპებისა და
   ზონების მიხედვით დივერსიფიკაციით (თავი 13).
4. **ტრაფიკი, ჟურნალები და საცავი** - gateway endpoint S3-ისთვის, NAT ზონების მიხედვით,
   ჟურნალების მოცულობა წყაროში, ტომები და snapshot-ები (თავები 31, 34, 23).

თანმიმდევრობა სწორედ ასეთია, რადგან ყოველი შემდეგი ნაბიჯი წინა ნაბიჯის მიერ შემცირებულ ბაზას
ეხება: გაბერილი მოცულობის დაკომიტება ან Spot-ზე გადატანა ფასიანი სიცარიელის დაფიქსირებას ნიშნავს.
