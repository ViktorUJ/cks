# Модель затрат кластера EKS: шаблон оценки

[Оглавление курса](README_RU.md) · [Глава 43](43/ru.md) · [Глоссарий](GLOSSARY_RU.md)

Это рабочая форма к главе 43: та же структура стоимости, но в виде таблицы и формул, по
которым инженер собирает оценку своего кластера. Нового материала здесь нет.

## Как этим пользоваться

- Форма НЕ содержит цен. Ставки зависят от региона, меняются и устаревают быстрее, чем
  курс, поэтому графа «Ставка (заполнить)» оставлена пустой намеренно.
- Ставки берут в AWS Pricing Calculator под свой регион и подставляют в пустую графу; для
  факта по уже работающему кластеру - из Cost and Usage Report (глава 43).
- Ценность шаблона не в точности числа, а в полноте перечня: он не даёт забыть статью,
  которая всплывёт в счёте, но не попала в оценку.
- Оценку делают дважды: ДО right-sizing и ПОСЛЕ. Разница между двумя прогонами и есть
  измеренный эффект инженерного решения, а не обещание экономии.
- Единицы держите одинаковыми по всей форме (часы в месяце, GB против GiB), иначе строки
  не складываются между собой.
- Прогоняйте форму заново после смены режима покупки нод, добавления AZ, включения новых
  типов логов и любого изменения топологии egress.

## Формулы в общем виде

```text
Обозначения: HOURS - часы в расчётном месяце, RATE_* - ставка из таблицы выше,
все величины потребления берутся из метрик и биллинга, а не из проектных планов.

control_plane = CLUSTERS * HOURS * RATE_CP
              + CLUSTERS_EXT * HOURS * RATE_CP_EXT_DELTA
# CLUSTERS_EXT - кластеры на версии в extended support: это НАДБАВКА к обычной
# почасовой плате за кластер, а не та же ставка (глава 38).

nodes = сумма по пулам P: NODES[P] * HOURS[P] * RATE_INSTANCE[P, режим покупки]
# режим покупки: On-Demand, Spot, покрытие Reserved или Savings Plans (глава 43).

auto_mode = nodes(пулы Auto Mode)                          # часть EC2
          + MANAGED_INSTANCES * HOURS * RATE_AM_MGMT       # наценка за управление
# ОБЯЗАТЕЛЬНО: Reserved Instances и Savings Plans снижают ТОЛЬКО часть EC2.
# Наценка за управление Auto Mode под эти скидки НЕ попадает и в счёте живёт
# отдельной позицией (глава 09). Почасовая плата за control plane EKS под
# Compute Savings Plans тоже не попадает (глава 43).

fargate = сумма по подам: VCPU_PROV * LIFETIME_H * RATE_VCPU
        + MEM_PROV_GB * LIFETIME_H * RATE_MEM
# VCPU_PROV и MEM_PROV_GB - выданная комбинация из аннотации CapacityProvisioned,
# то есть requests, округлённые вверх, а не сами requests (глава 15).

commit_base = BASELINE_COMPUTE - SPOT_SUSTAINED
# BASELINE_COMPUTE считают ПОСЛЕ right-sizing, иначе коммитится пустота.
# SPOT_SUSTAINED - устойчиво достигаемая доля Spot, а не проектная: Savings Plans
# не покрывают Spot, часовой коммит между часами не переносится и недобор сгорает
# каждый час, а fallback на On-Demand возвращает часть потребления под коммит
# (главы 43 и 13). Коммит пересматривают по факту utilization и coverage.

nat = NAT_COUNT * HOURS * RATE_NAT_HOUR
    + PROCESSED_GB * RATE_NAT_GB
# Две независимые части: за существование NAT и за каждый обработанный гигабайт.

cross_az = CROSS_AZ_GB * RATE_CROSS_AZ
# Тарифицируется в обе стороны: в CROSS_AZ_GB входит и запрос, и ответ (глава 31).

storage = сумма по томам: SIZE_GIB * RATE_VOLUME[тип]
        + SNAPSHOT_GIB * RATE_SNAPSHOT
# Платится заявленный размер тома, а не занятое внутри файловой системы.

logs = INGEST_GB * RATE_INGEST + STORED_GB * RATE_STORAGE
# INGEST_GB - принятый объём: он обычно и есть главная статья (глава 34).

total_month = control_plane + nodes + auto_mode + fargate
            + nat + cross_az + egress_internet + storage + logs
            + endpoints + load_balancers
```

## Что обычно забывают

- **Наценка Auto Mode.** В счёте это отдельная позиция сверх ставки EC2, и скидочные модели
  её не касаются; при сравнении Auto Mode со своим стеком её считают явно (глава 09).
- **Extended support как надбавка.** Кластер на устаревшей версии стоит дороже за час
  работы, а не столько же; в оценке это отдельное слагаемое (глава 38).
- **Cross-AZ в обе стороны.** Сервис в одной зоне, зовущий базу в другой, платит за обмен,
  а не только за запрос; считать оба направления (глава 31).
- **NAT берёт дважды.** Почасовая плата идёт, пока NAT существует, и независимо от неё
  платится каждый обработанный гигабайт; забывают обычно вторую часть (глава 31).
- **Логи платятся в основном за приём.** Урезание retention трогает только хранение и
  экономит слабо; работают интервал сбора, уровни логирования и фильтрация серий (глава 34).
- **Забытые тома и снапшоты.** PVC удалили, том остался; снапшоты копятся годами. Это
  тихая утечка, которую видно только в биллинге (глава 23).
- **Балансировщик после удалённого сервиса.** Service снесли не через Kubernetes, NLB или
  ALB остался жить и тарифицироваться (глава 26).
- **Idle-ёмкость.** Платите за зарезервированное requests, а не за использованное: разрыв
  между requested и used - оплаченная пустота, помноженная на реплики (глава 43).

## Порядок оптимизации

1. **Right-size и bin-pack** - привести requests к реальному потреблению и дать
   consolidation уплотнить ноды (главы 43, 14, 12).
2. **Коммит на устоявшийся baseline** - Savings Plans на объём, который держится месяцами,
   уже после сокращения (глава 43).
3. **Spot на гибкие нагрузки** - прерываемое переводят на Spot с диверсификацией по типам и
   зонам (глава 13).
4. **Трафик, логи и хранение** - gateway endpoint для S3, NAT по зонам, объём логов в
   источнике, тома и снапшоты (главы 31, 34, 23).

Порядок именно такой, потому что каждый следующий шаг применяется к базе, которую уменьшил
предыдущий: закоммитить или заспотить раздутый объём - значит зафиксировать оплату пустоты.

## Границы шаблона

- Форма не заменяет AWS Pricing Calculator для прогноза и Cost and Usage Report для факта:
  она задаёт перечень статей и формулы, а числа приходят оттуда.
- Прикладные сервисы вне кластера (базы данных, очереди, кеши, S3 под данные приложений)
  здесь не считаются, хотя в счёт продукта входят.
- Аллокация по командам и namespace делается инструментом аллокации из главы 43, а не этой
  таблицей: она про кластер целиком, а не про то, кто внутри сколько потратил.
- Shared-затраты (control plane, системные namespace, idle) форма показывает как строки
  кластера; правило их разнесения на команды выбирают отдельно (глава 43).
- Скидки по соглашениям с AWS и порядок применения коммитов форма не моделирует: их видно
  только в фактическом биллинге.
