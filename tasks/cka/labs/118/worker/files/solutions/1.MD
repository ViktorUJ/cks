# Lab 118 — reference solution (certificates, CoreDNS, cluster networking)

We save the reports on the work machine in the directory `/home/ubuntu/answers/`. We connect
to the control plane over SSH: `ssh k8s1_controlPlane_1`.

## Task 1. Certificate health check → `certs.txt`

The cluster certificates live on the control plane in `/etc/kubernetes/pki/`. We read them
with `openssl` ([official documentation: Certificate Management with kubeadm](https://kubernetes.io/docs/tasks/administer-cluster/kubeadm/kubeadm-certs/)).

```bash
ssh k8s1_controlPlane_1

# expiration date of the API server certificate
sudo openssl x509 -in /etc/kubernetes/pki/apiserver.crt -noout -enddate
# notAfter=Jul 20 10:00:00 2026 GMT   <- the value after "notAfter="

# CN of the cluster certificate authority
sudo openssl x509 -in /etc/kubernetes/pki/ca.crt -noout -subject
# subject=CN = kubernetes   <- CN = kubernetes

# a convenient overview of all expiration dates:
sudo kubeadm certs check-expiration
```

On the work machine write the report (the `notAfter` value — exactly the string after the
`=` sign):

```bash
mkdir -p /home/ubuntu/answers
cat > /home/ubuntu/answers/certs.txt <<EOF
apiserver_notafter=Jul 20 10:00:00 2026 GMT
ca_cn=kubernetes
EOF
```

> Substitute your own `notAfter` value from the `openssl` output.

## Task 2. Fix CoreDNS

CoreDNS is a Deployment in `kube-system`
([official documentation: DNS for Services and Pods](https://kubernetes.io/docs/concepts/services-networking/dns-pod-service/),
[Debugging DNS Resolution](https://kubernetes.io/docs/tasks/administer-cluster/dns-debugging-resolution/)).

```bash
kubectl -n kube-system get deploy coredns          # READY 0/0 — replicas zeroed out
kubectl -n kube-system scale deployment coredns --replicas=2
kubectl -n kube-system rollout status deploy coredns

# resolution check:
kubectl run dnstest --image=busybox:1.36 --restart=Never -it --rm -- \
  nslookup kubernetes.default
```

## Task 4. Lower ndots for a Pod (dnsConfig)

kubelet writes `/etc/resolv.conf` into Pods with `options ndots:5`: names with fewer than 5
dots are first tried with the search suffixes. For external names (`api.github.com` — 2
dots) those are useless NXDOMAIN queries. The threshold can be lowered for a Pod through
`dnsConfig`
([official documentation: DNS for Services and Pods — Pod DNS Config](https://kubernetes.io/docs/concepts/services-networking/dns-pod-service/#pod-dns-config)).

First a Pod with the default DNS:

```bash
kubectl run dns-default --image=viktoruj/ping_pong:alpine --restart=Never

# look at its resolv.conf: it will contain "options ndots:5"
kubectl exec dns-default -- cat /etc/resolv.conf
```

Then a Pod with a lowered `ndots` (declaratively, because `--dry-run` cannot do dnsConfig):

```yaml
# dns-tuned.yaml
apiVersion: v1
kind: Pod
metadata:
  name: dns-tuned
spec:
  dnsConfig:
    options:
    - name: ndots
      value: "2"
  containers:
  - name: c
    image: viktoruj/ping_pong:alpine
```

```bash
kubectl apply -f dns-tuned.yaml
kubectl get po dns-tuned -o jsonpath='{.spec.dnsConfig.options}'; echo
```

> Trade-off: `ndots:2` speeds up external names, but a call to a service in **another**
> namespace by the short name `backend.prod` (2 dots → already absolute) will no longer be
> completed through search. For external names an FQDN with a trailing dot is more
> reliable: `api.github.com.`.

## Task 5. ndots report → `dns.txt`

```bash
# the ndots value from the default Pod
kubectl exec dns-default -- cat /etc/resolv.conf | grep -oE 'ndots:[0-9]+'
# ndots:5

cat > /home/ubuntu/answers/dns.txt <<EOF
default_ndots=5
tuned_ndots=2
EOF
```

## Task 6. Find the Pod DNS name

Every Pod gets an A record following the formula:
`<pod-ip-with-dashes>.<namespace>.pod.cluster.local`
([official documentation: DNS for Services and Pods — Pod's A/AAAA record](https://kubernetes.io/docs/concepts/services-networking/dns-pod-service/#pods)).

```bash
# find the IP of Pod dns-test
kubectl get pod dns-test -n dns-lab -o wide
# NAME       READY   STATUS    IP           ...
# dns-test   1/1     Running   10.0.1.23    ...

# build the DNS name: replace the dots in the IP with dashes
# 10.0.1.23 → 10-0-1-23.dns-lab.pod.cluster.local

# check resolution (from any Pod with nslookup/dig)
kubectl exec dns-default -- nslookup 10-0-1-23.dns-lab.pod.cluster.local

# write the answer
echo "10-0-1-23.dns-lab.pod.cluster.local" > /home/ubuntu/answers/pod-dns-name.txt
```

> Substitute the real IP of your Pod.
