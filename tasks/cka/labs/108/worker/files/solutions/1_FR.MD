# Lab 108 — solution de référence (PV, PVC, pod avec un volume)

## Tâches 1-3. PV + PVC + pod sur le nœud node_2

```yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: pv-analytics
spec:
  capacity:
    storage: 100Mi
  accessModes: ["ReadWriteOnce"]
  hostPath:
    path: /pv/analytics
---
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: pvc-analytics
spec:
  accessModes: ["ReadWriteOnce"]
  resources:
    requests:
      storage: 100Mi
---
apiVersion: v1
kind: Pod
metadata:
  name: analytics
spec:
  nodeSelector:
    node: node_2
  containers:
  - name: analytics
    image: viktoruj/ping_pong:alpine
    volumeMounts:
    - name: data
      mountPath: /pv/analytics
  volumes:
  - name: data
    persistentVolumeClaim:
      claimName: pvc-analytics
```

```bash
kubectl apply -f pv.yaml
kubectl get pv,pvc
kubectl get po analytics -o wide     # doit tourner sur le nœud portant le label node=node_2
```

Remarques :
- Le PV et le PVC se lient automatiquement dès que la taille et l'accessMode correspondent.
- `nodeSelector: node=node_2` place le pod sur le nœud worker (c'est là que se trouve le hostPath `/pv/analytics`).
