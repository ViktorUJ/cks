# Lab 114 — reference solution (troubleshooting)

The diagnostic route is always the same: `get` → `describe` (Events) → `logs` → fix.

## Task 1. ReplicaSet rs-app2223 (ImagePullBackOff)

```bash
kubectl get po -n rsapp                 # STATUS: ImagePullBackOff
kubectl describe po -n rsapp <pod>      # Events: the image viktoruj/ping_pong:doesnotexist123 cannot be pulled
# fix the image in the RS template
kubectl edit rs rs-app2223 -n rsapp     # image: viktoruj/ping_pong:doesnotexist123 -> viktoruj/ping_pong:latest
# an RS does not recreate Pods itself when the template changes — delete the old Pods
kubectl delete po -n rsapp -l app=rsapp
kubectl get rs rs-app2223 -n rsapp      # READY 2
```

## Task 2. Service svc-broken (empty Endpoints)

```bash
kubectl get endpoints svc-broken -n tsvc   # empty
kubectl describe svc svc-broken -n tsvc    # selector app=WRONG
kubectl get pods -n tsvc --show-labels     # the Pods carry the label app=web
# fix the Service selector
kubectl patch svc svc-broken -n tsvc -p '{"spec":{"selector":{"app":"web"}}}'
kubectl get endpoints svc-broken -n tsvc   # the addresses have appeared
```

## Task 3. Deployment capp (CreateContainerConfigError)

```bash
kubectl get po -n cfgapp                  # CreateContainerConfigError
kubectl describe po -n cfgapp <pod>       # configMap missing-config not found
# create the missing ConfigMap
kubectl create configmap missing-config -n cfgapp --from-literal=KEY=value
kubectl rollout status deploy capp -n cfgapp
```
