# 第 0.8 章。vim を 15 分で：生き延びて YAML 向けに設定する

> **この章は誰のためか。** エディタ `vim` についての短い実践的な最小限です。CKA/CKAD の
> 試験でも、クラスタのノード上でも、これがデフォルトのエディタであり、あなたは絶えず
> これで編集することになります（マニフェスト、設定ファイル、`/etc/...`）。目的は
> 「vim をマスターすること」ではなく、vim で時間を失わないことです：開く、編集する、
> 保存する、抜ける、そして YAML 向けにインデントを正しく設定する。すでに vim を
> 自信をもって使えるなら、この章は飛ばしてください。

## 0.8.1. 二つのモード - まず理解すべき最重要事項

vim で初心者が混乱するのは、すべて **モード** のせいです。同じキーが、どのモードに
いるかによって違う働きをします。

```mermaid
flowchart LR
    normal["NORMAL<br>コマンド：移動、<br>削除、保存"] -->|"i を押す"| insert["INSERT<br>普通の文字入力"]
    insert -->|"Esc を押す"| normal
    style normal fill:#326ce5,color:#fff
    style insert fill:#0f9d58,color:#fff
```

- **NORMAL**（起動時のデフォルト）- キーは文字ではなくコマンドです。
- **INSERT** - 普通の文字入力。入るのは `i`、出るのは `Esc` です。

生き延びるためのルール：**何かおかしくなったら `Esc` を押す**（Normal に戻ります）、
それからコマンドを打ちます。

## 0.8.2. 生き延びるための最小コマンド集

このセットだけで、試験での作業の 95% は足ります：

| 動作 | キー（Normal モードから） |
|----------|----------------------------|
| 編集を始める | `i` |
| 編集を抜ける | `Esc` |
| 保存する | `:w` + Enter |
| 保存して抜ける | `:wq` または `ZZ` |
| 保存せずに抜ける | `:q!` |
| 取り消す / やり直す | `u` / `Ctrl+r` |
| 行を削除する | `dd` |
| 行をコピー / 貼り付け | `yy` / `p` |
| ファイルの先頭 / 末尾へ | `gg` / `G` |
| 検索 | `/テキスト` + Enter（次へ - `n`） |
| 行番号 | `:set number` |

ファイルを開く：`vim file.yaml`。これだけです。試験ではふつうこれ以上は必要ありません。

## 0.8.3. YAML 向けの設定 - 必須

Kubernetes を扱うときの vim の最大の困りごとは：**スペースの代わりにタブ** が入ることと、
インデントが「ずれていく」ことです。YAML はタブを禁止していますが（第 0.6 章）、vim は
デフォルトでタブを挿入することがあります。だから試験でまずやるのは `~/.vimrc` を
作ることです：

```vim
set expandtab       " Tab はタブではなくスペースを挿入する
set tabstop=2       " タブの幅 - スペース 2 個
set shiftwidth=2    " 自動インデントの幅 - スペース 2 個
set number          " 行番号
set autoindent      " 新しい行でインデントを保つ
syntax on           " シンタックスハイライト
```

この設定があれば Tab キーはスペース 2 個を入れ、マニフェストがインデントで壊れることは
ありません。`~/.vimrc` の設定は試験で **いちばん最初に** やる価値があります（これは
第 1 章の開始時の作業に含まれます）。

## 0.8.4. 貼り付け (paste) の落とし穴

`autoindent` を有効にしたまま Insert モードで（マウスで）できあいの YAML を vim に
貼り付けると、インデントが **どんどん増えていき** - 各行がますます右へずれていきます。
直し方はこうです：

```vim
:set paste      " 貼り付ける前に - 自動インデントを無効にする
" ... テキストを貼り付ける ...
:set nopaste    " 貼り付けたあとに - 普通のモードへ戻す
```

貼り付けたあとにインデントの「階段」が見えたら、これが原因です。`:set paste`、
取り消し（`u`）、もう一度貼り付け。

## 0.8.5. ミニ用語集

- **Normal モード** - vim のコマンドモード（デフォルト）。キーはコマンドです。
- **Insert モード** - 文字入力のモード。入るのは `i`、出るのは `Esc`。
- **`:wq` / `:q!`** - 保存して抜ける / 保存せずに抜ける。
- **`~/.vimrc`** - vim の設定ファイル（インデント、行番号）。
- **`expandtab`** - タブをスペースに置き換える（YAML では決定的に重要）。
- **`:set paste`** - 自動インデントなしの貼り付けモード（「階段」対策）。

## 0.8.6. 本章のまとめ

- vim には二つのモードがあります：Normal（コマンド）と Insert（テキスト）。切り替えは
  `i` と `Esc`。迷ったら - `Esc` を押しましょう。
- 生き延びるための最小限：`i`、`Esc`、`:wq`、`:q!`、`u`、`dd`、`/検索`、`:set number`。
- YAML 向けには `~/.vimrc` の設定が必須です（`expandtab`、`tabstop=2`、`shiftwidth=2`）-
  そうしないとタブがマニフェストを壊します。
- できあいのテキストを貼り付けるときは `:set paste` を使って、インデントが「ずれない」
  ようにしましょう。

## 0.8.7. これがどう役に立つか：試験と実際の仕事で

**試験では。** エディタは 2 時間ずっと使い続ける主要な道具です。vim との格闘で失った
分数は、解けなかった問題そのものです。設定済みの `~/.vimrc` と十数個のコマンドが、
マニフェストを扱うすべての問題で時間を節約します。

**実際の仕事では。** vim はどの Linux ノードにもインストールなしで入っています - SSH で
サーバー上の設定を直すとき、ほかに選択肢がないことも多いです。vim の基本的な操作は
エンジニアに必須のスキルです。

## 演習

この章には独立したラボはありません：vim はこのあとのすべてのラボとモック試験で、
マニフェストを編集しながら使っていきます。`~/.vimrc` を一度設定すれば - インデントの
問題は忘れられます。次からは本編のコースが始まります - 第 1 章です。
